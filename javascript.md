### Вопросы

#### Типы данных

**Вопрос:** На какие категории делятся типы данных в JavaScript? Чем отличаются эти категории?

**Ответ:** Примитивы(простые/базовые) и объекты(сложные/ссылочные). Примитивы иммутабельны сами по себе. Объекты состоят из примитивов и могут быть мутабельны.

Фронтендеры любят отвечать что-то вроде "передаются по ссылкам", о чем им рассказывают в туториалах. Тут необходимо уточнить, что под этим подразумевается.

Проверка кодом:
```js
var count = 10;
var obj = { count };

function incrementNumber(value) {
  value = value + 1;
}

function incrementCountObject(value) {
  value.count = value.count + 1;
}

incrementNumber(count);
incrementCountObject(obj);

console.log(count); // ?
console.log(obj.count); // ?
```

#### hoisting

**Вопрос:** В чем разница между `var` и `let`?

**Ответ:** Рассказывает про блочную область видимости `let`. Рассказывает про поднятие `var`.

**Вопрос:** Помимо `var` что еще обладает поднятием(hoisting)?

**Ответ:** декларации именованных функций через `function`

Проверка кодом:
```js
var foo = 1;

function run() {
  foo = 10;

  function foo() {
    return 20;
  }

  console.log(foo); // ?

  var foo = 30;
}

run();

console.log(foo); // ?
```

#### Области видимости

**Вопрос:** что такое замыкание?

**Ответ:** существуют области видимости переменных. В JavaScript, не считая глобальной области видимости(которая по умолчанию представляет из себя глобальный объект), бывают функциональные и блочные. Области определяются лексически, в момент объявления функции/блока. Мы, после объявления, можем передать эту функцию куда-нибудь, при этом область ее видимости никак не изменится, а переменные объявленные в этой области будут жить в памяти, пока жива функция.

Проверка кодом:
```js
for (var i = 0; i < 10; i++) {
  setTimeout(() => {
    console.log(i); // ?
  }, 0);
}
```

Как исправить? А не меняя `var` на `let`? А не указывая третий аргумент `setTimeout`?

#### Контекст

**Вопрос:** Что такое контекст? (контекст выполнения функции, `this`)

**Ответ:** это неявный аргумент функции, к которому можно получить доступ по ключевому слову `this`. Стрелочные функции не обладают собственным контекстом, для них `this` берется из замыкания.

Фронтендеры не любят выражение "область видимости" и не очень любят "замыкание". Могут сказать "где объявляется". Не обращаем внимание.

**Вопрос:** Как он определяется?

**Ответ:** в момент выполнения функции. Обычно это `то, что стоит перед "точкой" в выражении вызова функции`. Но можно задать контекст явно, через `call`, `apply`, `bind`. Если у функции нет забинженного контекста и "перед точкой" ничего нет, то "контекст теряется" и будет использован глобальный контекст.

**Отличный ответ:** use strict при потере контекста устанавливает undefined, а без use strict это глобальный объект. Нестандартные контекст так же наблюдается с оператором `new`, там объект, прототип которого указан в статическом свойстве `prototype` функции

**Вопрос:** в чем разница между `call`, `apply` и `bind`?
**Ответ:** `call` и `apply` вызывают функцию, и отличаются только сигнатурой. `bind` создает новую функцию, прикрепляя указанный контекст и, опционально, аргументы.

Проверка кодом:
```js
'use strict';

var obj = {
  fn: function () {
    return this;
  }
}

var fn = obj.fn;

console.log(obj.fn()); // ?
console.log(fn()); // ?
```

#### ООП

**Вопрос:** как устроено ООП в JavaScript?

**Ответ:** в JavaScript прототипное наследование. У каждого есть поле, в которое может быть записана ссылка на прототип. В момент обращения к свойству объекта, если у объекта есть собственное свойство с таким названием, то будет возвращено значение из этого свойства, иначе такая проверка будет рекурсивно применена к прототипу, до тех пор, пока цепочка прототипов не кончится. По умолчанию все цепочки заканчиваются на `Object`

**Отличный ответ:** ...но есть `Object.create(proto)` и можно создать объект без прототипа. А еще есть Proxy (оставим за кадром).

**Вопрос:** если все на прототипах, что такое классы?

**Ответ:** синтаксический сахар.

**Отличный ответ:** уже не совсем синтаксический сахар (появились, как минимум, приватные поля, к которым нет доступа даже у Proxy)

Проверка кодом:
```js
class Parent {
  log() {
    console.log('parent');
  }
}

class A extends Parent {
  log() {
    console.log('a');
  }
}

class B extends Parent {}

var a = new A();
var b = new B();

a.log(); // ?
b.log(); // ?

delete a.log;
delete b.log;

a.log(); // ?
b.log(); // ?

delete Parent.prototype.log;

a.log(); // ?
b.log(); // ?
```

#### Асинхронность

**Вопрос:** Прежде чем отвечать про JavaScript, что такое "асинхронность" как понятие в программировании?

**Ответ:** Неважно что, главное чтобы кандидат понимал разницу между "асинхронностью" и "многопоточностью". Если не понимает, попробуем кратко объяснить.

Справка: JavaScript с 2017 года стал многопоточным языком, ведь в спецификации языка описались потоки и межпоточное взаимодействие. Большинство фронтендеров до сих пор не в курсе и говорят "JavaScript однопоточный", не обращаем внимание.

**Вопрос:** Как работает асинхронность в JavaScript?

**Ответ:** рассказывает про EventLoop. Рассказывает про разные очереди задач и разницу. Макротаски(или просто таски) - выполняются в ограниченном количестве за итерацию. Микротаски - выполняются до полной очистки очереди микротасок.

**Отличный ответ:** рассказывает что есть очередь RAF (requestAnimationFrame), она разгребается перед(в старом Safari после) отрисовкой фрейма, и разгребаются все таски бывшие в очереди на момент начала отрисовки(новые RAF будут ждать следующей отрисовки)

Проверка кодом:
```js
// Три независимые строчки. Где будет блокировка?

while (true) {} // ?
function loop1() { setTimeout(loop1, 0); }; loop1(); // ?
function loop2() { return Promise.resolve(loop2) }; loop2(); // ?
```
