## React

Проводим кандидатам уровня не выше Middle. Более сильным кандидатам проводить смысла нет, так как они способны хорошо изучить React за пару недель, если не меньше.

### Основные вопросы

Задаем всегда

#### Что такое React и для чего он нужен? Что должно быть в React-приложении, и чего не должно там быть?

Ожидаем что кандидат понимает, что React это лишь библиотека для рендера UI с использованием компонентного подхода.

Отлично, если кандидат понимает, что React-приложение не должно непосредственно содержать логику других слоев: работа с API, глобальное состояние и прочее. Только UI и использование API других слоев через адаптеры.

#### Каких практик ты стараешься придерживаться при работе с React? Как разделяешь код?

Ожидаем что кандидат хотя бы знает о практике разделения на "умные" и "глупые" компоненты(контейнеры и вьюхи).

Отлично, если расскажет почему именно так, и какие конкретно ограничения на каждую категорию компонент.

#### Что такое Redux и зачем он нужен? Какие знаешь альтернативы? Использовал effector?

Просто узнаем кругозор кандидата в плане сторов. Опыт работы с effector будет плюсом.

### Опциональные вопросы

Их можно задать кандидату, если есть подозрения что кандидат слабо знает React

#### Что такое хуки, для чего они нужны? Какие знаешь и используешь? Как писать кастомные хуки?

Хуки - это API React для использования в функциональных компонентах.

Ожидаем что кандидат кратко расскажет про основные хуки:
* useEffect/useLayoutEffect (отлично, если расскажет про разницу)
* useState
* useRef (отлично, если расскажет что туда можно записывать не только DOM-элементы)
* useMemo/useCallback

#### Что такое HoC(хоки)? Для чего они нужны?

HoC - компонент высшего порядка, по сути обертки над компонентами.

#### Что такое контекст и зачем он нужен? Какую проблему решает?

Контекст нужен для неявной передачи данных глубже по дереву. Решает проблему "props drilling", когда появляются большие цепочки компонент, которые передают пропсы глубже, не используя их самостоятельно.

#### В Redux-сторе необходимо хранить текущую позицию скролла, как будешь делать?

Нам достаточно, если знает что изменения в сторе приводят к синхронному ререндеру React-приложения, к которому подключен стор. Заодно можно убедиться что кандидат знает как использовать Redux.

Ожидаем что кандидат знает про throttle/debounce, если кандидат забыл упомянуть про этот паттерн, то подсказываем "ок, все работает, но при скролле лагает, как исправить?".
